 # Gameplay, persistence, and UI audit

Reviewed 2026-10-05. This is a source-code audit of the client, server, market logic, and migration-defined database behavior. Findings below describe the checked-in code; deployed database policies and migrations were not inspected. No gameplay code was changed.

Validation: all 73 client tests across 12 suites passed; server tests passed; client and server TypeScript checks (`tsc --noEmit`) passed. Additional local checks reproduced the slippage split-order discrepancy and found simultaneous news impacts that the infinite engine drops. Authenticated browser flows, real network failure scenarios, mobile rendering, and database migrations were not exercised against a live service.

Major means progress loss, incorrect cash/trades, broken rewards, or compromised competitive results. Minor means a narrower progression, display, feedback, or recovery defect. Text-cut suggestions are editorial judgments, not bugs.

## Major bugs

| ID | Finding and player impact | Evidence / reproduction | Fix direction |
| --- | --- | --- | --- |
| B01 | **The client can invent trade prices, wealth, holdings, and achievement unlocks.** Competitive scores and progression are not trustworthy. | `supabase/migrations/202607020001_open_ended_gameplay.sql:23` accepts `target_price` without deriving/checking the market quote. `server/src/routes/gameRoutes.ts:77` writes submitted net worth. Ownership policies in `202606240001_stock_simulator_schema.sql:279` and `202606240006_cloud_saves_achievements_leaderboard.sql:39` allow direct session/holding/unlock writes. RLS restricts whose data changes, not whether the gameplay change is valid. | Validate gameplay transitions and derive prices, balances, XP, and scores in trusted operations; restrict direct writes to competitive state. |
| B02 | **Loading a Day 1 save can resume at the later cached day instead.** Cash/holdings rewind while the market does not, and the next advance can charge intervening bills. | Save on Day 1, advance to Day 20, then load that save in the same session/browser. `client/src/context/GameContext.tsx:651` chooses cached Day 20 when the restored database day is 1, then writes it back. | Treat the restored database day as authoritative; remove or explicitly isolate the legacy local-day recovery. |
| B03 | **A stale trade can use an old price or rewind the session.** | `Game.tsx:61` retains a whole stock object in the trade dialog. The global ArrowRight handler at line 201 remains active while the dialog is open, allowing day progression without refreshing that stock object. Separately, the trade RPC writes `current_day = target_game_day` (`202607020001_open_ended_gameplay.sql:140`) without requiring it to equal the current session day. An older tab can therefore trade at its old day/price and move the database backward. | Resolve the current quote at confirmation, block conflicting in-flight actions, and reject stale day/version requests on the server. |
| B04 | **Mission and daily-goal XP rewards do not increase player XP.** | `pages/GoalsMissions.tsx:19` advertises XP and `hooks/useMissions.ts:161` says it was earned. `hooks/useLevel.ts:33`, `hooks/useAchievements.ts:423`, and SQL `player_total_xp` in `202607310001_leaderboard_player_levels.sql:3` count achievement unlocks only. | Either award these rewards through the shared XP calculation or remove the reward promises. |
| B05 | **Paid advisors are lost across devices and are not restored with cloud saves.** Loading an earlier save can also keep an advisor while refunding the cash used to hire them. | `hooks/useAdvisor.ts:117` stores ownership only under a browser-local session key. `pages/SaveLoad.tsx:109` stores no advisor ownership. Loading a save into another session uses that destination session's advisor state. | Persist ownership with the run and include it in save/restore transactions. |
| B06 | **Advisor payments can silently fail or overwrite newer cash.** | `GameContext.tsx:1031` changes React cash first and ignores the database update result; `addCash` writes an absolute balance from captured state. `useAdvisor.ts:136` then records successful ownership. A rejected write produces a free local advisor; a concurrent trade from another tab can have its new balance overwritten. | Make hiring and the cash debit one checked, atomic database operation. |
| B07 | **Restoring a save does not restore a coherent trade history/journal.** | `202608270001_restore_save_slot_bill_clock.sql:23` restores cash/day/mode/seed/holdings but leaves the destination session's trades and journal untouched. Restore an earlier snapshot after trading: Dashboard still shows the later trades; delayed reviews can discuss decisions from the abandoned timeline. Loading a different run into that session mixes histories. | Define snapshot semantics explicitly and restore/truncate or branch session-scoped history consistently. |
| B08 | **A completed challenge's score can still change or disappear.** | `GameContext.tsx:1171` calls Day 30 complete, but `executeTrade` and StockDetails buy/sell do not check completion. The leaderboard reads mutable day-30 sessions (`202607310001_leaderboard_player_levels.sql:98`). Trading/hiring changes final net worth; restoring an earlier save into the same active session moves it off Day 30 and removes the finish from the board. | Finalize a challenge once and preserve its result independently of subsequent restore/play actions. |
| B09 | **Loading an older save can permanently lose a level-up cash reward.** | Save before earning an infinite-mode level reward, earn it, then restore. The restore rewinds cash, but `profiles.last_level_reward_processed` remains advanced (`202607310002_infinite_level_cash_rewards.sql:91`); achievement XP also remains unlocked. That reward will not be paid again. | Reconcile account-wide reward claims with restored run cash so a restore neither deletes an entitlement nor duplicates payouts. |
| B10 | **Deleting one account clears other accounts' local game data on the same browser.** | `pages/Profile.tsx:198` removes every `stockpilot-` key. This includes other users' inboxes, streaks, tutorials, and session advisor ownership, not just the deleted account. | Remove only keys belonging to the deleted user and that user's sessions. |

No run identity is stored. | Include session/run identity in persistence and cache keys. |
| B12 | **Cloud saves do not remember market-open versus after-hours state.** A revealed-news save loads with hidden news on another device; a same-day restore may inherit the destination's phase. | Phase is only in localStorage (`GameContext.tsx:647,692`); the save payload contains no phase (`SaveLoad.tsx:109`). | Save the phase with the snapshot and restore it explicitly. |

| B16 | **Trade errors are misreported as insufficient cash/shares.** | Any false result from the RPC becomes “Not enough cash” or “Not enough shares” in `Game.tsx:277` and `StockDetails.tsx:189,195`, including connectivity, session, and database failures. | B21 | **Profile loading can spin forever after one failed profile fetch.** | `AuthContext.tsx:65` only settles `profileUserId` on success, with no error state or retry; `Profile.tsx:212` renders the spinner while the IDs differ. | Expose a recoverable load error and retry action. |
| B22 | **Light custom themes still receive dark-theme text colors.** | `ThemeContext.tsx:423` calls `makePalette(customInput)` with its default `dark` mode. | B23 | **Trade reviews appear in the Missions folder instead of Advisor.** | `hooks/useTradeDebriefs.ts:82` sets `category: "mission"` for messages from “Your Advisor.” The Advisor inbox filter will omit them. | Use the advisor category. |
| B24 | **“Cloud Save Active” is shown even when save requests fail.** | `pages/SaveLoad.tsx:393` is unconditional. It remains green after fetching/saving fails and reflects no storage health check. | Show a real save status/time or remove the status claim. |

## Balance and deployment concerns to decide or verify

These are separate from the 24 bugs above because the desired rule or deployment state is not fully established by the code.

- **Split orders bypass the anti-snowball mechanic.** With $2,000 net worth and a $100 quote, one 10-share buy costs $1,120, while ten 1-share buys cost $1,000. `tradingState.ts:40` considers only the current order. If the intended rule is daily position-size pressure, aggregate turnover or exposure; if it is per-order slippage, document that small orders are allowed to avoid it.
- **Unpaid bills disappear.** The advance RPC marks the billing cycle paid through even when it only collects part of the bill. Investing all cash before the due day avoids almost the entire expense. Decide whether forgiveness is intentional; otherwise store arrears or apply a defined consequence. See `202609180001_reduce_weekly_living_expenses.sql:53`.
- **The rival has different costs and share rules.** It holds fractional shares and pays no weekly bills or slippage (`useRivalTrader.ts:52`), while the player uses whole shares and pays expenses. This is acceptable as a benchmark, but it is not an equal-rules trading opponent.
- **Migration versions are duplicated.** `202607240003` appears on both daily-goal and infinite-leaderboard migrations; `202607310001` appears on both player-level and stock-alert migrations. Verify the actual migration runner/history before a fresh deployment; the files need distinct version identifiers for version-based tracking. No migrations were applied during this audit.
- **Long infinite runs need a browser performance test.** Full price histories and all historical news are regenerated as the day changes; the 5,000-entry impact cache clears wholesale. The 10,000-day client cap prevents unbounded input but does not establish acceptable frame time at that cap. See `GameContext.tsx:265,410,754`.

After-hours trading was checked and deliberately excluded as a bug: the tutorial and Game's next-step copy explicitly tell players to read after-hours news and trade before advancing.

Recommended order: fix B01–B03 first, then make saves/purchases/rewards consistent (B05–B10), then reconcile XP (B04), then address the smaller defects and text cleanup.
